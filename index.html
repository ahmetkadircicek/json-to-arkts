    Usage

    Convert JSON to ArkTS classes for HarmonyOS

    ArkTS, the language of HarmonyOS and OpenHarmony apps, does not allow any or untyped object literals, so every JSON response needs a typed model class. Paste a sample response and get ready-to-use .ets classes with fromJson and toJson, written to pass the ArkTS linter in DevEco Studio.

    1. Paste JSON

      A sample API response, or a list of objects. Format tidies it up, and an error shows its line and column.

    2. Pick a style

      Default values, optional or nullable fields, private fields with getters and setters, @Observed or @ObservedV2 with @Trace.

    3. Add it to your project

      Copy or download the .ets file, or a .zip with one file per class, into a folder such as entry/src/main/ets/model.

    Frequently asked questions

    How do I parse JSON in ArkTS?

    Cast the parsed value to Record<string, Object> and pass it to the generated fromJson: User.fromJson(JSON.parse(text) as Record<string, Object>). To turn a model back into text, call JSON.stringify(user.toJson()).

    Why not just cast JSON.parse to a class?

    A cast does not create an instance. The object has no methods, no default values and no @Observed proxy, so the UI does not react to its changes. fromJson builds real class instances, nested objects and lists included.

    Does the generated code pass ArkTS strict mode?

    Yes. It uses no any or unknown and types every object literal and lambda parameter. Every combination of options is tested with the ArkTS linter of ohos-typescript, the compiler DevEco Studio builds ArkTS with.

    Should I use @Observed or @ObservedV2?

    Use @Observed with @ObjectLink in state management V1. For state management V2 (API 12 and later), choose @ObservedV2: every field gets @Trace, so changes to nested objects update the UI.

    What happens to null and missing fields?

    With default values, a missing or null key keeps the field's default: 0, '', false or []. Optional fields read as undefined and nullable fields as null. toJson leaves undefined and null fields out.

    Is my JSON sent anywhere?

    No. The converter is plain JavaScript that runs in your browser, and your last JSON and options are kept only in your own browser. The page counts visits anonymously with Cloudflare Web Analytics, without cookies: the page, the referring site, the country and the browser type, never your JSON or code. Browsers with Do Not Track or Global Privacy Control are not counted.

    Does it work with OpenHarmony and HarmonyOS NEXT?

    Yes. HarmonyOS NEXT, HarmonyOS and OpenHarmony apps all use ArkTS, so the classes work in any of them.
